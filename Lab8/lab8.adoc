= Отчёт «Что я узнала на 8 лекции про ОСРВ»
:author: Дидык Анна

== Введение

ОСРВ (операционные системы реального времени) — это программы, которые помогают нам реагировать на события строго в заданные сроки.  
Основная их задача — обеспечить **timeliness**, то есть своевременную обработку данных.

Примеры квантов реакции в разных областях:  
* Математическое моделирование — несколько микросекунд  
* Радиолокация — несколько миллисекунд  
* Складской учёт — несколько секунд  
* Управление производством — несколько минут  

Есть два типа ОСРВ:  
* **«Мягкие»** (soft real time) — если система чуть-чуть опоздала, она остаётся работоспособной (например, обычный ПК: «Программа не отвечает»).  
* **«Жёсткие»** (hard real time) — пропуск квантов времени недопустим, иначе система может «упасть» (например, контроллеры встраиваемых устройств).

== Принцип работы

ОСРВ создаёт иллюзию одновременного выполнения нескольких задач на одном ядре — это называется **псевдомногозадачностью**.

Существует два способа переключения задач:  
* **Кооперативный** — задача сама уступает управление после завершения или в заранее определённой точке.  
* **Вытесняющий** — ОСРВ прерывает текущую задачу, если появляется задача с более высоким приоритетом.

Принцип работы очень похож на принцип прерываний:  
. Выполняется задача A.  
. При системном тике (прерывание) планировщик сохраняет её контекст (регистры, стек, указатель на строку).  
. Планировщик выбирает готовую задачу B (по приоритету).  
. Восстанавливает её контекст и начинает выполнять B.  
. При следующем тике или завершении B возвращается к A или переходит к другой задаче.

== Системный тик

Системный тик — это прерывание от специального таймера (SysTick в Cortex-M).  
Часто его настраивают на 1 мс, но можно менять в зависимости от требований.

Каждый тик — это «квант времени» для задач: именно в момент тика ОСРВ запускает планировщик.

== Пример без ОСРВ

[source,c]
----
for (;;) {
    GreenLed.Toggle();
    delay(OneSecond);
}
----

Добавим мигание красным раз в 2 с:

[source,c]
----
uint8_t secondCounter = 0;
for (;;) {
    while (++secondCounter <= 1) {
        GreenLed.Toggle();
        delay(OneSecond);
    }
    secondCounter = 0;
    RedLed.Toggle();
}
----
Если затем нужно мерить температуру каждые 40 мс, код становится неудобным.

== Пример с ОСРВ

[source,c]
----
Led GreenLed(GreenPin, 1000U);
Led RedLed(RedPin,   2000U);
Temperature Temp(40U);

int main() {
    Rtos::CreateTask(&GreenLed, GreenLedStackSize, GreenLedPriority, "GreenLed");
    Rtos::CreateTask(&RedLed,   RedLedStackSize,   RedLedPriority,   "RedLed");
    Rtos::CreateTask(&Temp,     TempStackSize,     TempPriority,     "Temp");
    Rtos::StartScheduler();
}

void GreenLed::Execute() {
    for (;;) {
        Toggle();
        Sleep(period);
    }
}

void RedLed::Execute() {
    for (;;) {
        Toggle();
        Sleep(period);
    }
}

void Temperature::Execute() {
    for (;;) {
        Measure();
        Sleep(period);
    }
}
----

Теперь ОСРВ сама переключает задачи по системному тику и приоритетам, а каждая задача выполняется с нужным периодом.

== Вывод

Я узнала, что ОСРВ:  
* Упрощают написание кода для периодических задач.  
* Обеспечивают жёсткие или мягкие временные гарантии.  
* Позволяют легко масштабировать систему, добавляя новые задачи.  
* Делают логику устройств независимой от механизма планирования.

= Лабораторная работа 2

== 1. Типы данных, их размер, преобразование типов и указатели


=== Типы данных
В C есть базовые типы:
* `char` (1 байт, символ)
* `int` (обычно 4 байта)
* `float` (обычно 4 байта, дробные числа)
* `double` (обычно 8 байт, более точные дробные числа)
* `void` (специальный тип, обозначает "ничего", например, `void` у функций, которые ничего не возвращают)


А также модификаторы: `short`, `long`, `signed`, `unsigned`.

=== Как вычисляется размер
Размер вычисляется через `sizeof(тип)` или `sizeof(переменная)`. Например, `sizeof(int)` обычно 4 байта.

=== Преобразование типов
* **Неявное преобразование (implicit cast):** Автоматически меняется тип данных, например, при сложении `int` и `double` результат будет `double`.
* **Явное преобразование (explicit cast):** Когда мы сами указываем, как менять тип, например:  

[source,cpp]
----
double x = 3.14;
int y = (int)x; // явное преобразование
----

* `static_cast` используется, когда преобразование логично (например, `double` в `int`).
* `reinterpret_cast` просто меняет представление памяти (например, `int*` в `char*`), что опасно.

**Почему преобразование плохо?**  
Потому что можно потерять данные (например, `double` в `int` обрежет дробную часть).

=== Указатели
* **Что такое указатель?**  
Это переменная, которая хранит адрес в памяти. Например:  

[source,cpp]
----
int a = 5;
int* ptr = &a; // ptr теперь указывает на a
----

* **Операции с указателями:**  
  `*` (разыменование), `&` (взятие адреса), `+` и `-` (арифметика указателей), `==` и `!=` (сравнение).

**Почему нельзя вычитать указатели разных объектов?**  
Потому что это не имеет смысла – они могут быть из разных участков памяти, и разница будет бессмысленной.

=== Работа с битами
* Установить бит: `x |= (1 << n);`
* Сбросить бит: `x &= ~(1 << n);`
* Переключить бит: `x ^= (1 << n);`

== 2. Что делают унарный `+` и `-`
* `+` ничего не делает, просто показывает, что число положительное.
* `-` меняет знак числа.

[source,cpp]
----
int x = 5;
int y = -x; // y = -5
----

== 3. Почему `17 000 000 + 1 == 17 000 000` в `float`?
В `float` (4 байта) есть ограниченная точность (около 7 знаков).  
Когда число большое, оно хранится в экспоненциальной форме, и прибавление `1` просто **не изменяет мантиссу**, потому что дробная часть слишком мала, чтобы `float` мог её учесть.

== 4. Почему `7 != 7` в коде?
* `7.7f / 1.1f` в `float` не дает ровно `7`, из-за потерь точности. Скорее всего, результат `6.999999` вместо `7.000000`.
* `float` не всегда хранит точные числа, особенно при делении. Например, `7.7f / 1.1f` может получиться `6.99999999`, а не `7.0f`, поэтому сравнение `magicSeven == Seven` не срабатывает.

[source,cpp]
----
#include <iostream>
#include <iomanip>

float GetMagicSeven(float num) {
    return 7.7f / 1.1f;  // тут появляется ошибка округления
}

int main() {
    const float Seven = 7.0f;
    float magicSeven = GetMagicSeven(Seven);

    // установим точность вывода
    std::cout << std::fixed << std::setprecision(10);

    if (magicSeven == Seven) {
        std::cout << "7f == 7f" << std::endl;
    } else {
        std::cout << "7f != 7f" << std::endl;
        std::cout << "magicSeven: " << magicSeven << std::endl;
        std::cout << "Seven: " << Seven << std::endl;
    }

    return 0;
}
----

=== Пример вывода программы:
----
7f != 7f
magicSeven: 6.9999995232
Seven: 7.0000000000
----

== Работа с GPIO
Также на паре разобрались, как **вручную включать и выключать светодиоды**, вместо того чтобы использовать готовые команды типа `GPIOA::ODR::ODR5::High::Set();`. Теперь мы **напрямую работаем с регистрами**, записывая в них нужные значения.

Раньше мы просто писали что-то вроде:
[source,cpp]
----
// GPIOA::ODR::ODR5::High::Set();
----

А теперь мы сами указываем **адрес регистра** и изменяем его значение, чтобы включить светодиоды:

[source,cpp]
----
volatile std::uint32_t* const ptrGpioaOdr =
  reinterpret_cast<volatile std::uint32_t*>(0x40020014);
  
*ptrGpioaOdr |= (1U << 5U);  // Включаем светодиод на PA5
----

То есть, мы **прямо записываем в память микроконтроллера**, управляя ножками GPIO **без библиотек**. Теперь лучше понимаем, как это все работает "под капотом".

=== Полный код:
[source,cpp]
----
for(;;)
{
    //GPIOA::ODR::ODR5::High::Set();
    volatile std::uint32_t* const ptrGpioaOdr =
      reinterpret_cast<volatile std::uint32_t*>(0x40020014);
    volatile std::uint32_t* const ptrGpiocOdr =
      reinterpret_cast<volatile std::uint32_t*>(0x40020814);
    delay(1000000);
    
    *ptrGpioaOdr |= (1U << 5U);
    *ptrGpiocOdr |= (1U << 9U);
    *ptrGpiocOdr |= (1U << 8U);
    *ptrGpiocOdr |= (1U << 5U);
    
    delay(1000000);
    
    //GPIOA::ODR::ODR5::Low::Set();
    *ptrGpioaOdr &= ~(1U << 5U);
    *ptrGpiocOdr &= ~(1U << 9U);
    *ptrGpiocOdr &= ~(1U << 8U);
    *ptrGpiocOdr &= ~(1U << 5U);
}
----

== Вывод
* **Преобразования типов** могут быть **неявными** (автоматическими) и **явными** (`(тип)переменная`).
* **Проблемы `float`** – не всегда точные числа, поэтому `7 != 7` из-за ошибок округления.
* **Битовые операции** (`|, &, ^`) позволяют **манипулировать числами на уровне битов**.
* **Указатели** нужно использовать **осторожно**, особенно при арифметике, чтобы **не выйти за границы допустимой памяти**.
* Теперь мы **понимаем, как устроена работа с регистрами GPIO**, а не просто вызываем готовые функции.

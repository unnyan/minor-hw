= Отчёт «Что я узнала на лекции про RTOS (FreeRTOS)»
:author: Дидык Анна

== Введение

FreeRTOS — это бесплатная небольшая операционная система реального времени для встраиваемых устройств.  
Её ядро помещается всего в 3–4 файла, и её легко порти­ровать на разные микроконтроллеры (более 35 архитектур).  

Планировщик FreeRTOS поддерживает:  
* **Вытесняющую** и **невытесняющую** многозадачность  
* Приоритеты задач  
* Семафоры, очереди, события и уведомления задач для синхронизации  

== Задача (Task)

**Задача** — это мини-подпрограмма с бесконечным циклом:  
* Имеет свою точку входа (`TaskFunction`) и не выходит из неё  
* Имеет отдельный стек памяти  
* Имеет приоритет и имя  

=== Состояния задачи

1. **SUSPENDED** – «успокоена», не выполняется и ждёт явного `vTaskResume()`  
2. **READY** – готова к запуску, ждёт, когда диспетчер выделит ей квант  
3. **RUNNING** – диспетчер запустил её код, она активно выполняется  
4. **WAITING** – ждёт какого-то события (таймаут, очередь, семафор)  

=== Переходы между состояниями

* _Создание_ задачи (`xTaskCreate`) → SUSPENDED → READY  
* _Диспетчер_ по приоритету переводит READY → RUNNING  
* _Окончание кванта_ или _появление более приоритетной_ READY-задачи → RUNNING → READY  
* _Ожидание_ (delay, очередь, событие) → RUNNING → WAITING  
* _Событие случилось_ → WAITING → READY  
* _Удаление_ задачи (`vTaskDelete`) → задача выгружается  

== Создание и задержка задачи

Для создания задачи используется API:

[source,c]
----
BaseType_t xTaskCreate(
    TaskFunction_t pxTaskCode,        // функция задачи
    const char * const pcName,        // имя для отладки
    uint16_t usStackDepth,            // размер стека
    void *pvParameters,               // параметр задачи
    UBaseType_t uxPriority,           // приоритет
    TaskHandle_t *pxCreatedTask       // (опционально) указатель на handle
);
----

Чтобы приостановить задачу на заданное время, есть:

[source,c]
----
void vTaskDelay( const TickType_t xTicksToDelay );
----
где `xTicksToDelay` — количество тиков системного таймера (обычно 1 тик = 1 мс).

== Межзадачная коммуникация

FreeRTOS предоставляет несколько механизмов для обмена данными и синхронизации:

=== 1. Очереди (Queues)

Очередь — буфер FIFO для передачи структур или указателей между задачами и/или прерываниями.  
* `xQueueCreate(length, item_size)` – создать очередь  
* `xQueueSend()` / `xQueueReceive()` – отправить/принять элемент  
* При `xQueueReceive(..., portMAX_DELAY)` задача блокируется до появления элемента  

_Пример_:  
При нажатии кнопки в ISR добавляем код кнопки в очередь. Задача-обработчик делает `xQueueReceive`, ждёт данные, и как только что-то приходит, разблокируется и читает значение.

=== 2. События (Event Groups)

Event Group — битовая маска, где каждая задача может ждать установку одного или нескольких битов:  
* `xEventGroupCreate()` – создать  
* `xEventGroupSetBits()` – установить биты (ISR-безопасно)  
* `xEventGroupWaitBits()` – ждать установки нужных бит  

=== 3. Уведомления задач (Task Notifications)

Лёгковесный механизм: у каждой задачи есть один 32-битный счётчик-уведомление:  
* `xTaskNotifyGive()` / `ulTaskNotifyTake()` – передача и приём уведомления  
* Очень быстрый и не требует дополнительной памяти  

=== 4. Почтовый ящик (Mailbox)

Специфичный примитив для передачи указателей на сообщения; во FreeRTOS часто строится на очередях с длиной 1.

== Итоги

На лекции я поняла, что FreeRTOS:  
* Позволяет легко разделять приложение на независимые задачи с разными приоритетами  
* Даёт понятные состояния задач и чёткий жизненный цикл  
* Предоставляет готовые примитивы для синхронизации и обмена данными  
* Подходит даже для очень ограниченных устройств благодаря компактному ядру

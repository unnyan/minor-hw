= Отчёт «Что я узнала на 7 лекции про прерывания»
:author: Дидык Анна

== 1. Как работают прерывания и какие они бывают

Прерывание — это сигнал микроконтроллеру: «Стоп, тут срочно нужно сделать кое-что другое».  
Они бывают трёх типов:

– Аппаратные (асинхронные)::  
  Приходят от внешних устройств — кнопок, датчиков, таймеров.  
– Синхронные (исключения)::  
  Возникают внутри ядра — деление на ноль, неправильная инструкция.  
– Программные::  
  Вызываются явно из кода специальной командой (например, SVC).

Аппаратные IRQ-линии дополнительно делятся на:  
* Маскируемые — их можно включать/отключать контроллером NVIC.  
* Немаскируемые (NMI) — всегда «проходят» (например, сигнал аварийного сбоя питания).

Когда приходит прерывание, Cortex-M:
. Завершает текущую инструкцию и сохраняет часть регистров на стек.
. Проверяет в NVIC, разрешено ли это прерывание и какой у него приоритет.
. Берёт из таблицы векторов адрес функции-обработчика и прыгает туда.
. По окончании ISR восстанавливает контекст и продолжает основную программу.

== 2. Контроллер прерываний NVIC

NVIC (Nested Vectored Interrupt Controller) — это «диспетчер» внутри ядра Cortex-M, который:
* Включает и выключает каждую линию IRQ.
* Определяет, какое прерывание важнее, если их несколько одновременно.
* Поддерживает вложенность: ISR с более высоким приоритетом может прервать ISR с более низким.
* Автоматически запускает нужный обработчик по адресу из таблицы векторов.

== 3. Таблица векторов прерываний

Таблица векторов — это массив указателей на все обработчики (ISR), расположенный в начале памяти микроконтроллера:
. Элемент 0 — стартовый указатель стека.
. Элемент 1 — адрес сброса (Reset).
. Элемент 2 — NMI.
. Элемент 3 — HardFault.
. Далее — остальные исключения ядра, а затем внешние IRQ (TIM2, USART1 и т. д.).

При наступлении IRQ №N NVIC берёт адрес ISR из ячейки `2 + N` этой таблицы.

== 4. Обработчик прерывания (ISR) и правила его написания

ISR — это функция, которая вызывается «по звонку» от NVIC.  
Главные правила:

* Сразу сбросить аппаратный флаг прерывания, чтобы его не повторять.
* Минимум работы внутри ISR: отметить событие, положить данные в буфер или поднять флаг.
* Не блокироваться: никаких задержек, `while`-циклов ожидания, `printf`, `malloc`.
* Не вызывать не-реентрантные функции без защиты.
* Тяжёлую работу перенести в основной код (через флаги, очереди, задачи).

== 5. Пример: прерывание по переполнению TIM2

=== 5.1. Настройка таймера

[source,c]
----
htim2.Init.Prescaler = 8400 - 1   // делим 84 МГц на 8400 → 10 кГц
htim2.Init.Period    = 10000 - 1  // считаем до 10000 → 1 секунда
HAL_TIM_Base_Init(&htim2)
HAL_TIM_Base_Start_IT(&htim2)     // запускаем с прерываниями
----

=== 5.2. Включение IRQ в NVIC

[source,c]
----
HAL_NVIC_SetPriority(TIM2_IRQn, 1, 0)
HAL_NVIC_EnableIRQ(TIM2_IRQn)
----

=== 5.3. Обработчик и колбек

[source,c]
----
void TIM2_IRQHandler(void) {
    HAL_TIM_IRQHandler(&htim2);  // сброс флага UIF и вызов колбека
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM2) {
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5); // мигаем светодиодом
    }
}
----

=== 5.4. Механизм работы

Когда счётчик достигает `Period`, в таймере поднимается флаг UIF.  
NVIC замечает запрос от TIM2 и вызывает `TIM2_IRQHandler`.  
Внутри HAL сбрасывает UIF и вызывает колбек, где мигает светодиод.  
По окончании ISR Cortex-M восстанавливает контекст и возвращается к основному коду.

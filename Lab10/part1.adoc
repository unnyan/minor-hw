== 1. Типы регистров в ARM-M

=== 1.1 Регистры общего назначения

- **R0–R3, R12** («scratch»): рабочие регистры, любой код может их менять без предварительного сохранения.  
- **R4–R11** (callee-save): вспомогательные регистры, функцию нужно сохранить их значение на входе и восстановить на выходе.  
- **R13 (SP)**: указатель стека.  
- **R14 (LR)**: адрес возврата из функции.  
- **R15 (PC)**: программный счётчик, показывает текущую инструкцию.

=== 1.2 Специальные регистры

- **xPSR** (Program Status Register): флаги состояния приложения и процессора.  
- **Interrupt Mask Registers** (PRIMASK, FAULTMASK, BASEPRI): маскирование прерываний.  
- **CONTROL**: выбор уровня привилегий и процесса работы с двумя стеками (MSP/PSP).

== 2. Аппаратные регистры периферии

Переферийные модули (таймеры, UART, GPIO и т. д.) управляются специальными регистрами в ОЗУ: каждая ячейка — 32 бита, а внутри поля (несколько бит) отвечают за конкретную функцию.

=== 2.1 Описание поля регистра

- **Адрес**: 32-битный шестнадцатеричный указатель (например, `0x4001 0000`).  
- **Длина**: число бит (1…32), определяет диапазон значений поля (2ⁿ).  
- **Режим доступа**: RW (чтение/запись), RO, WO.  
- **Value enum**: в C++-обёртке каждому значению поля присвоено имя `Value0`, `Value1` и т. д., но для ясности можно менять их на более понятные (Disable/Enable).

==== Пример «в лоб» на C

[source,c]
----
int main() {
    // установить бит 0 (CEN) регистра TIM1->CR1
    *reinterpret_cast<volatile uint32_t *>(0x40010000) |= (1u << 0);
    return 0;
}
----

==== Пример с C++-обёрткой

[source,c++]
----
int main() {
    // RCC::CR::HSEON — поле Enable внешнего осциллятора
    RCC::CR::HSEON::Enable::Set();
    return 0;
}
----

== 3. Регистры GPIO

Каждый GPIO-порт имеет набор регистров:

- **GPIOx_MODER** (mode): выбор режима (Input/Output/Analog/AltFunc)  
- **GPIOx_OTYPER** (type): push-pull или open-drain  
- **GPIOx_OSPEEDR** (speed): скорость переключения (2, 25, 50, 100 MHz)  
- **GPIOx_PUPDR** (pull-up/down): подтяжка к VCC или GND или «no pull»  
- **GPIOx_IDR** (input data): текущее состояние входов  
- **GPIOx_ODR** (output data): управление уровнем на выходах  

=== 3.1 Цифровой выход и вход

- **Output High/Low**: запись `1` или `0` в ODR приводит к подключению ножки к VCC или GND соответственно.  
- **Floating Input**: сопротивление входа очень велико, без подтяжки «ножка плавает» и может ловить шум.  
- **Input Pull-Up/Pull-Down**: внутренний резистор фиксирует уровень, убирая ложные срабатывания и паразитный ток.
